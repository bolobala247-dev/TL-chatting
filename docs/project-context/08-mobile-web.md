# 08 — Mobile & Web Platform Specifics

## Mobile

### Expo / React Native CLI

- **Expo SDK 56, managed workflow with CNG** (Continuous Native Generation): `android/` is regenerated by `expo prebuild` on every EAS build; a local `android/` copy exists for direct Gradle builds (`how-to-build-local.md`).
- Builds: EAS profiles `development` (dev client, internal), `preview` (APK, internal), `production` (APK, autoIncrement, internal distribution; Play submit config expects AAB — a documented conflict). CI: `.eas/workflows/build-android-production.yml`.
- Native tuning injected by the config plugin `plugins/withGradleBuildOptimizations.js` (heap, parallel, caching, PNG crunch off).
- New Architecture + Hermes; release ABIs `armeabi-v7a` + `arm64-v8a`.
- iOS: configured in `app.json` (tablet support, WebRTC camera/mic permission strings in Vietnamese) but no EAS iOS profile settings beyond defaults, no push support, and no iOS build documentation in the repo.

### Navigation

Expo Router native Stack: headers hidden globally, `fullScreenGestureEnabled` swipe-back, custom `FloatingTabBar` for the three tabs, route groups `(auth)`/`(tabs)`, dynamic route `chat/[roomId]`. Typed routes enabled.

### Storage

- **SecureStore**: Supabase session (custom adapter), app-lock PIN hash + salt + biometrics flag (`talo_app_lock_*`), push token + synced marker (`tl-push-token*`), install ID (`tl-install-id`).
- **AsyncStorage**: theme (`talo.theme-preference`), language (`talo-language`), drafts (`talo-drafts`), recent emojis (`talo-recent-emojis`).

### Push Notifications

- Android-only, physical devices only, Expo Push token keyed by EAS `projectId`; notification channel `messages` (HIGH importance, vibration). Registered on mount + every foreground return; per-install UUID prevents cross-device token deletion; token removed on sign-out; dead tokens pruned server-side.
- Delivery pipeline: DB trigger → pg_net → edge function → Expo Push API → FCM (FCM V1 key uploaded to EAS credentials; `google-services.json` at repo root). **Push does not work in Expo Go** (noted in `ANDROID_PUSH_SETUP.txt`).
- Foreground suppression for the active room; tap navigates to `/chat/{roomId}` (cold-start and warm handled via `useLastNotificationResponse` with dedup).

### Background Tasks

**None on the client.** No `expo-background-fetch`/`expo-task-manager` usage found in repository. Background work is server-side (pg_cron scheduled messages; push delivered by FCM while the app is killed).

### Deep Links

- Scheme: `talo` (`app.json`).
- Password-reset email redirects into the `(auth)/reset-password` screen (`detectSessionInUrl` on web; `expo-linking` present).
- Notification taps deep-link to chat rooms. `AuthGate` delays link handling until session initialization completes.

### Other Mobile Features

- **App lock**: PIN (SHA-256 with random UUID salt, single round) + optional biometrics (`expo-local-authentication`, device-credential fallback disabled); locks on cold start and on background; attempt limit with cooldown. Native-only (SecureStore has no web backend). Documented as a UI gate, not encryption.
- **Calls**: P2P WebRTC (`react-native-webrtc`), `react-native-incall-manager` for audio routing, iOS PiP via RTCPIPView (iOS 15+).
- **Haptics**: web-safe wrappers around `expo-haptics` (selection for swipes/toggles, medium impact for long-press menus).

## Web

### Next.js Architecture

**Next.js is not used.** The web app is the same Expo codebase exported with Metro (`web.bundler: "metro"`, `web.output: "static"` in `app.json`; `npm run build` = `npx expo export -p web`), served by Vercel as a static SPA (`vercel.json`: `cleanUrls`, rewrite `/:path*` → `/index.html`, immutable caching for `_expo/static` and `assets`).

### SSR / CSR / RSC

- **SSR**: none — static export only.
- **CSR**: everything; the SPA hydrates client-side and all data comes from Supabase at runtime.
- **RSC**: none — no server components, no API routes (confirmed: the only server-ish file is the static `+html.tsx` shell).

### SEO & Metadata

`app/+html.tsx` provides the static HTML shell: title "Talo", meta description, `theme-color #000000`, favicons + apple-touch-icon, manifest link, full OpenGraph tags (1200×630 `og-image.png` hosted at the Vercel site URL) and Twitter `summary_large_image` card, plus `ScrollViewStyleReset`. Because output is a static SPA, all routes share this single head — no per-route metadata; deep pages are not individually crawlable with unique titles/descriptions.

### Dynamic Routes

`chat/[roomId]` works client-side; the Vercel rewrite sends every path to `index.html` and Expo Router resolves the route in the browser. No static generation of dynamic paths.

### Image Optimization

No web-specific image optimization (no Next/Image, no CDN transforms). `expo-image` on web + Supabase Storage public URLs served as-is. Static assets get immutable cache headers.

### PWA

`public/manifest.json`: standalone display, portrait, `lang: vi`, maskable 192/512 icons, black theme color — the app is **installable**, but there is **no service worker**, so no offline capability and no web push.

### Web Platform Splits

`.web.tsx`/`.web.ts` files replace native-only modules: `VercelInsights.web.tsx` (Analytics + Speed Insights; native file is a no-op), `webrtc.web.ts` (browser globals, `WEBRTC_SUPPORTED` feature detection, PiP off), `callAudio.web.ts`, `RemoteVideo.web`, `VideoStream.web`. Web-guarded code paths: notifications module (stubbed on web), SecureStore usage, haptics, app lock (disabled on web).
